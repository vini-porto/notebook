# S2: Escopo, compile-time vs run-time, imports

1. **Escopo = onde um nome existe**, e quem define são as `{ }`. Cada bloco é uma sala com vidro espelhado: de dentro você enxerga o de fora, de fora não enxerga o de dentro. Variável criada dentro de um `for`/`if` morre no `}`. O que precisa lembrar entre voltas ou ser usado depois (soma, contador, maior) é declarado **fora** do loop.
2. **O compilador só vê nomes e tipos, nunca valores.** Nome inexistente, tipo errado ou `;` faltando → **compile-time**, e o programa **nem começa** (nenhuma linha roda). Índice, tamanho de array, `null`, divisor zero são valores → **run-time**: roda até a linha e quebra com uma exception. Tamanho NÃO faz parte do tipo (`int[]`), então `notas = new int[100]` pode trocar o array.
3. **As 4 exceptions clássicas:** `ArrayIndexOutOfBounds` (último índice = `length - 1`; `<` e não `<=` no loop) · `StringIndexOutOfBounds` (`isEmpty()` antes de `charAt`) · `NullPointerException` (checar `== null` antes de usar) · `ArithmeticException: / by zero` (só com `int`; com `double` dá `NaN`, sem erro!). Defesa: **guard clause** no começo do método, e a ordem importa.
4. **Ler stack trace:** `Exception in thread "main"` = run-time. Tipo + mensagem dizem O QUÊ; a primeira linha `at ...` com arquivo seu diz ONDE (método + linha); as de baixo dizem QUEM CHAMOU. Compile-time aparece como `Arquivo.java:linha: error: cannot find symbol`.
5. `import pacote.Classe;` traz **classes**. `import static pacote.Classe.membro;` traz **membros `static`** (`max`, `PI`) para usar sem `Math.`. `java.lang` (String, Math, System) é importado sozinho. Arrays: `length` sem parênteses (field), String: `length()`, List: `size()`. `new int[3]` começa com `[0, 0, 0]`, e `new String[3]` com `[null, null, null]`.
